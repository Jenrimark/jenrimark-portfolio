# 成品交付计划与内部审核点

用户已通过首屏并明确授权后续由代理自行审核，不再等待逐模块人工确认。该授权覆盖技能原先的用户验收闸门。仍保持一次一个主要任务，依次实施与验证。

1. 内容与履历：以最新简历为依据，完成教育、两段实习、校园经历、技能与荣誉。审核真实来源、年份与占位项清理。
2. 作品：八个案例，网页原生图形封面、分类、文件夹展开、详情、上下案例、关闭与键盘操作。原生封面是主题视觉，不能伪装成真实产品截图。审核每个案例与简历对应、无虚构截图和指标。
3. 滚动叙事：沿用冻结人物，用代码实现上下滚动可逆的场景与文字转场；不伪称已生成额外视频。减少动态效果回退，移动端完整可读。
4. CMS：本地 Node 管理服务，中文表单编辑作品/履历/站点设置、封面上传、草稿预览、发布和下线。登录、同源检查、文件格式限制、草稿隔离。发布生成静态站并可推送到本项目独立 GitHub Pages 仓库。
5. 成品审核：真实浏览器桌面/手机、关键交互、控制台、资源、自动测试、后台真实作品草稿→预览→发布→更新→撤回闭环。
6. 发布：新建或复用专用于此次成品的独立仓库，不更改 D:/jenrimark.github.io 未提交代码；公开网址再次验收。交付站点、后台启动入口、源码与使用说明。

默认技术：HTML/CSS/JavaScript + Node 内置 HTTP/测试，独立静态构建。CMS 绑定本机，仅发布静态产物，草稿与登录凭据不进入公开构建或 Git。
